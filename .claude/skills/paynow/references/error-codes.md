# PayNow 錯誤碼表

> 來源：docs.paynow.com.tw/developer/docs/apipdf/cashflow/cashflow-errorcode、
> .../cashflow-paynowapi_js（退款 R 系列、交易查詢回應）。此為**舊版 CashFlow（體系 2）**錯誤碼。
> 體系 1（REST）以回應 `status` + `type`（`validation_error`/`rejected`/`failed` 等）+ `message` 表達，
> 退款另有 `RejectReason`；體系 3（發票）以 `status` + `message` 表達（文件未提供完整發票錯誤碼表，見文末 GAP）。

## 10. 體系 1 REST 狀態碼

REST API 回應外層 `status`（HTTP-like 數字）+ `type` + `message`：

- 成功：`status=200`、`type="success"`。
- 退款 `type` 可能為：`success` / `failed` / `rejected`（原因在 `RejectReason`）/ `processing` / `validation_error`。
- HTTP 狀態：退款開立可能回 `200` / `400`（請求錯誤）/ `422`（資料驗證失敗）。
- 詳細業務錯誤訊息在 `message` 欄位。

> **GAP**：官方文件未提供體系 3（發票）與體系 1（REST）的完整數字錯誤碼對照表，
> 只能依回應 `message` 判讀。若需要完整發票錯誤碼，建議洽 PayNow 客服或登入後台查閱。
