# ezPay 電子發票 錯誤代碼

對應 EZP_INVI_1.2.1 第九章「錯誤代碼」。所有 API 失敗時，回應的 `Status` 欄位
（成功為 `SUCCESS`）會帶下列錯誤代碼之一。錯誤代碼分五個前綴系列：

| 前綴 | 系列 |
|------|------|
| `KEY` | 金鑰 / 傳輸 / 解密相關 |
| `INV` | 發票業務邏輯相關 |
| `LIB` | 自訂編號 / 作廢相關 |
| `IAI` | 作廢折讓相關 |
| `NOR` | 網路相關 |

| `KEY10011` | PostData_ 欄位空白 | `PostData_` 未帶或為空 |
| `KEY10012` | 資料傳遞錯誤 | |

## 依 API 分類的常見錯誤

| API | 常見錯誤碼 |
|-----|-----------|
| 開立發票 `invoice_issue` | `KEY10002`（解密）、`INV10003`（商品格式）、`INV10004`（小計計算）、`INV10012`（金額驗證）、`INV10013`（欄位不齊）、`INV10014`（自訂編號格式）、`INV10017`（版本不支援混合稅率）、`INV90006`（張數用罄）、`LIB10003`（自訂編號重覆）|
| 觸發開立發票 `invoice_touch_issue` | `KEY10002`、`KEY10004`、`INV10013` |
| 作廢發票 `invoice_invalid` | `INV20006`（查無發票）、`INV70002`（上傳失敗不得作廢）、`LIB10005`（已作廢過）、`LIB10007`（已開折讓無法作廢）、`LIB10008`（超過作廢期限）、`LIB10009`（未上傳財政部無法作廢）|
| 開立折讓 `allowance_issue` | `KEY10002`、`INV10003`、`INV10004`、`INV20006`、`INV10013` |
| 觸發確認/取消折讓 `allowance_touch_issue` | `KEY10002`、`INV10013` |
| 作廢折讓 `allowanceInvalid` | `IAI10001`~`IAI10006` |
| 查詢發票 `invoice_search` | `KEY10002`、`INV20006`（查無發票）|

## 錯誤處理建議（zenbu-site 整合）

| 錯誤類別 | 處置 |
|----------|------|
| `KEY10002` 解密錯誤 | 多半是 AES padding / HashKey / HashIV 設定問題——檢查加密實作（見 concepts.md），**不要重試** |
| `KEY10010` / `KEY10011` / `KEY10013` 資料空白 | 程式組裝 body 的 bug，修正後再送 |
| `INV10003` / `INV10004` / `INV10012` 金額 / 商品計算錯誤 | 後端金額計算邏輯有誤，修正後再送（見 api-reference.md「金額計算」）|
| `LIB10003` 自訂編號重覆 | `MerchantOrderNo` 已用過——查既有發票，或換新編號 |
| `INV90006` 張數用罄 | 通知營業人到平台新增發票字軌號碼，暫停開立 |
| `LIB10008` / `LIB10009` / `LIB10007` / `INV70002` 作廢限制 | 不可作廢的業務狀態——改走開折讓（`allowance_issue`）或人工處理 |
| `NOR10001` / `KEY10014` 網路 / TimeOut | 短暫性錯誤——可重試（重試時用**完全相同**的 `PostData_`，平台對相同 `PostData_` 冪等回原發票）|
