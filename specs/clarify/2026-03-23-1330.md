# Clarify Session 2026-03-23 13:30

## Idea

優化 PayUni v3 信用卡金流模組的 webhook order_note 內容。目前 webhook 回調寫入的訂單備註只有簡單的 "PayUni Webhook: Payment successful"，希望能帶入更多交易細節資訊（如 TradeNo、卡號末四碼等），讓商家查看訂單備註時能更清楚這筆交易的詳情。

涉及 4 個 order_note 寫入點：
1. Bootstrap.php L204 -- webhook 重複通知冪等路徑
2. TradeHandler.php L169 -- webhook 到達但訂單已付款（idempotent path B）
3. TradeHandler.php L195 -- webhook 首次成功付款
4. TradeHandler.php L197 -- process_payment 前景授權成功

需要釐清：order_note 內容格式、哪些欄位要帶入、各路徑是否需區分不同備註內容。

## Q&A

- Q: 訂單備註要顯示哪些交易欄位？ → A: B — 與 v1 對齊 + 分期資訊。欄位：狀態碼、交易訊息、交易編號、卡號末四碼、授權碼；若有分期則加上：期數、首期金額、每期金額（共 5~8 個欄位）
- Q: 備註格式 → A: A（HTML 格式，與 v1 對齊），使用 `<strong>` 標題 + `<br>` 分行
- Q: 前景路徑是否也改 → A: A（統一改成結構化 HTML）
- Q: 冪等路徑的備註 → A: B（簡單標記，不帶交易細節），內容為「PayUni Webhook：重複通知，已略過」
- Q: 失敗路徑的備註 → A: A（也改成結構化 HTML）
- Q: 標題措辭 → A: Webhook 成功為「統一金流 PAYUNi 交易紀錄（Webhook）」；前景授權成功為「統一金流 PAYUNi 交易紀錄（前景授權）」；失敗為「統一金流 PAYUNi 信用卡付款失敗」；冪等為「PayUni Webhook：重複通知，已略過」
- Q: 是否需要統一的 helper method 生成備註 HTML？ → A: Yes（合理預設，避免 HTML 拼接散落多處）
- Q: 改動範圍確認 → A: TradeHandler::update_order_status() 的 3 個寫入點 + Bootstrap::handle_notify() 的 1 個冪等寫入點，共 4 處

### Round 2: LABEL_MAP 驅動全欄位輸出重構

- Q1: 欄位輸出策略（只印已知 key / 印整個 array 用 mapper / 印整個 array 原始 key） → A: 印出整個 $trade_result array，用 mapper 將已知 key 轉成中文 label，未知 key 直接顯示原始 key name
- Q2: 空值處理（有值才印 / 全部印） → A: A — 有值才印 `isset($v) && $v !== ''`，空字串欄位不顯示
- Q3: 分期欄位處理（保留群組條件 / 走通用邏輯） → A: A — 保留 `CardInst > 1` 群組條件，CardInst/FirstAmt/EachAmt 三個欄位仍以群組方式控制，僅分期交易才顯示，其餘走通用邏輯
- Q4: LABEL_MAP 存放方式（類別常數 / 方法內陣列 / 獨立設定檔） → A: A — 類別常數 `private const LABEL_MAP = [...]`，放在 TradeHandler 類別頂部
- Q5: 欄位顯示順序（LABEL_MAP 順序優先 / trade_result 原始順序 / 字母排序） → A: A — 按 LABEL_MAP 定義順序優先印已知欄位，再印不在 MAP 裡的未知 key（未知 key 之間按原始順序）
- Q6: 欄位排除策略（排除敏感/技術欄位 / 不排除任何欄位） → A: B — 不排除任何欄位，全部印出，管理員需要完整可見性
