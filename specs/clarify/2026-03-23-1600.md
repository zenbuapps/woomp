# Clarify Session 2026-03-23 16:00

## Idea

不分期的卡號付款失敗(帶上不分期卡號就會付款失敗)時：
1. 有收到 webhook 嗎? order_note 沒顯示
2. 付款明明失敗， order 卻改變狀態為 [處理中]|[完成]，應該要維持為 [等待付款中] 才對

## Q&A

- Q: 付款失敗的觸發方式為何？(A) PayUni sandbox + 特定失敗測試卡號 (B) 正式環境真實交易失敗 (C) 手動修改 API 回應模擬 → A: A — 在 PayUni sandbox 中使用 PayUni 提供的「付款失敗」測試卡號
- Q: 使用哪張測試卡號？以什麼流程觸發失敗？ → A: 使用一次付清卡號 `4147631000000001`，選擇分期付款流程，因卡號不支援分期而失敗
- Q: 付款失敗後，是否注意到訂單狀態在什麼時間點從「等待付款中」變為「處理中/完成」？ → A: C — 不確定，沒有注意到中間過程
- Q: 訂單的 order_note 實際內容為何？ → A: order_note 顯示「統一金流 PAYUNi 交易紀錄（前景授權）」，狀態碼 SUCCESS，交易訊息「建立幕後3D成功」，但交易編號、卡號末四碼、授權碼全部為空。確認根因：process_payment 的前景路徑把 PayUni 的「建立3D驗證成功」（Status=SUCCESS）誤判為「付款成功」，呼叫了 payment_complete()，但此時交易根本還沒完成
- Q: 3D 流程（raw_response 不含 EncryptInfo）時，process_payment 應如何處理？(A) 不呼叫 update_order_status()，維持「等待付款中」，僅存 meta 紀錄 3D 建立成功，由 webhook 決定 (B) 呼叫 update_order_status() 但跳過 payment_complete，設為自訂中間狀態 → A: A — 不呼叫 update_order_status()，維持訂單為「等待付款中」，僅儲存 meta 紀錄 3D 建立成功，由後續 webhook 決定付款結果
- Q: 3D 建立成功時，除了不呼叫 update_order_status() 外，還需要記錄什麼？(A) 僅 log，不存 meta (B) 儲存 `_payuni_v3_resp` meta + 寫一條 order_note 記錄「3D 驗證已建立，等待 webhook 回傳交易結果」（含 Status、Message）→ A: B — 儲存 `_payuni_v3_resp` meta + 寫一條 order_note 記錄「3D 驗證已建立，等待 webhook 回傳交易結果」（含 Status、Message）

## 澄清結論

所有問題已釐清，共 6 題。根因確定為 `CreditV3::process_payment()` 在 3D 流程（`raw_response` 不含 `EncryptInfo`）時，仍呼叫 `update_order_status()`，導致 `Status=SUCCESS`（僅代表「建立幕後3D成功」）被誤判為「付款成功」。修正後兩個問題（訂單狀態錯誤 + webhook order_note 不顯示）同時解決。
