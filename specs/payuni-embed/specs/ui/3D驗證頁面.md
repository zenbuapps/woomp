# 3D 驗證頁面

## 描述
當 API3D=1 時，PayUni merchant_trade API 回傳 3D 驗證 URL。
瀏覽器需跳轉至該 URL（銀行 3D Secure 頁面）進行持卡人身份驗證。
**非 SDK iframe 內處理，而是瀏覽器跳轉（Redirect）。**

## 流程（來源：PayUni 官方時序圖）
1. merchant_trade API 回傳 EncryptInfo，解密後含 `Status=SUCCESS`（建立幕後3D成功）和 `URL`（3D 導頁網址）
2. 商店 Server 將消費者瀏覽器重定向至 3D 驗證 URL
3. 消費者在銀行頁面完成驗證（OTP、指紋等）
4. 銀行回傳付款結果至統一金流
5. 統一金流透過 ReturnURL（Form POST）將頁面導回商店（前景通知）
6. 統一金流同時透過 NotifyURL（Webhook）背景通知交易結果

## 注意事項
- **測試區無 3D 跳轉步驟**：sandbox 環境會跳過實際的銀行 3D 驗證
- ReturnURL 若未設定，付款後呈現 PayUni 付款結果頁
- 交易結果以 NotifyURL (Webhook) 為準，ReturnURL 僅為前景導向
- 系統不控制銀行 3D 頁面的 UI

## 回應結構（merchant_trade 3D 回應）
EncryptInfo 解密後：
- `Status`: SUCCESS = 建立幕後3D成功（非付款成功）
- `Message`: 建立幕後3D成功
- `URL`: 3D 導頁網址（需重定向至此）
