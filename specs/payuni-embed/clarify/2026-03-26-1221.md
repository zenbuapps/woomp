# Clarify Session 2026-03-26 12:21

## Idea

調整 PayUni V3 定期定額付款閘道的 V1/V3 共存策略。

原始設計（Q8 決策）：透過後台設定 `payuni_subscription_version`（select: v1/v3）由管理員決定只顯示其中一個。

用戶新需求：不需要「定期定額版本」下拉選單，改為用 WooCommerce 原生的閘道啟用/停用來控制。如果管理員同時啟用 V1 和 V3 的定期定額閘道，結帳頁兩個都顯示。

影響範圍：
1. 移除 `payuni_subscription_version` option 和相關邏輯
2. 移除 `includes/payuni/settings/gateway.php` 中的「定期定額版本」select 欄位
3. 簡化 `SubscriptionBootstrap::filter_gateways_by_version()` — 不再需要
4. 更新 `SubscriptionBootstrap::conditional_payment_gateways()` — 移除版本互斥邏輯

待澄清：
1. 購物車同時有訂閱商品和非訂閱商品時，V1/V3 訂閱閘道的顯示行為
2. 消費者看到兩個訂閱閘道（V1 和 V3）時，如何區分？method_title 是否需要調整？
3. 既有 V1 訂閱的消費者換卡時，是否允許切換到 V3 閘道？

## Q&A

- Q: 購物車同時包含訂閱商品和一般商品時，V1/V3 訂閱閘道應如何顯示？ → A: 維持現狀（選項 A），WC Subscriptions 自行處理混合購物車限制，SubscriptionBootstrap 只需判斷「購物車有無訂閱商品」，混合購物車的限制交給 WC Subscriptions 處理。
- Q: 消費者在結帳頁面同時看到 V1 和 V3 兩個定期定額閘道時，method_title 應如何顯示讓消費者能分辨？ → A: 用付款體驗差異區分（選項 B）。V3 叫「信用卡定期定額（免跳轉）」，V1 維持「信用卡定期定額」。
- Q: 既有 V1 訂閱的消費者在 My Account 執行「更改付款方式」時，是否允許切換到 V3 閘道？ → A: 允許跨版本切換（選項 A）。換卡時看到所有已啟用的訂閱閘道，可自由選擇。換卡後訂閱的 payment_method 更新為所選閘道，後續續扣走新閘道邏輯。
