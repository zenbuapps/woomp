## 關鍵澄清結果

### 3D vs 非3D 流程
- **非3D**：merchant_trade 同步回傳完整授權結果（Status/TradeNo/Card4No）
- **3D**：merchant_trade 回傳 3D 驗證 URL，瀏覽器導頁至銀行，結果由 Webhook + ReturnURL 回傳
- **UNKNOWN**：銀行回應逾時（>60秒），後續由 Webhook 補送

### SDK Token
- 有效期 10 分鐘，透過 /iframe/token_get 取得
- 測試區無 3D 步驟（sandbox 跳過實際 3D 重導）

### 已儲存卡片（useDefault）
- SDK iframe 僅顯示 CVC 輸入框（CardNo/CardExp 隱藏）
- 消費者仍需輸入安全碼驗證身份

### Token 儲存
- CreditHash 比對防重複（string comparison）
- Sandbox 環境 CreditLife 為空時 fallback 到期日 12/2099
- BIN 偵測卡片類型：4=visa, 5=mastercard, 37=amex, 6=discover

### 發票載具
- 捐贈碼長度上限 7 碼（僅長度驗證）
- 買方名稱為空時自動 fallback 至帳單姓名（billing_first_name + billing_last_name）
- 會員載具不需額外載具資訊

### 退費
- 支援部分退費，$amount 直接傳至 PayUni API
- 金額上限由 PayUni API 驗證，系統僅驗證 > 0

### 金流設定
- 保留在結帳 Activity 中作為 STEP:1（一次性後台設定），不另建 Activity
