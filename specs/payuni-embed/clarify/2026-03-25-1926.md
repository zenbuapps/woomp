# Clarify Session 2026-03-25 19:26

## Idea

PayUni V3 定期定額付款闸道：为 WooCommerce Subscriptions 整合 V3 UNi Embed API 的约定信用卡（CreditHash tokenization）功能。

跟 V1 一样的架构，首次付款改用 UNi Embed iframe：
- 首次付款：UNi Embed iframe -> token_get -> merchant_trade（取得 CreditHash）
- 续扣执行：api/iframe/merchant_trade + CreditHash（server-side，无需 iframe）
- 排程管理：WC Subscriptions hook
- 订阅生命周期：暂停、恢复、取消、换卡、金额变更

需要新增/修改的文件：
- includes/payuni/src/gateways/CreditSubscriptionV3.php -- 新 Gateway class
- includes/payuni/v3/ 下新增 Subscription 相关逻辑（续扣 handler）
- includes/payuni/v3/Infrastructure/Http/TradeHandler.php -- 可能需要扩展支援纯 token 续扣
- includes/payuni/v3/Bootstrap.php -- 注册新 gateway 与 subscription hooks

前置条件待确认：
1. V3 的 merchant_trade endpoint 在纯 token 续扣时（没有 iframe session）是否正常运作
2. WooCommerce Subscriptions 外挂是否已安装在测试环境
3. V3 的 CreditHash response 格式与 V1 是否一致

## Q&A

- Q: V3 定期定額閘道的 gateway id 應該叫什麼？ → A: payuni-credit-subscription-v3（選項 A，與 V1 對稱 + v3 後綴）
- Q: V3 續扣應該使用哪個 PayUni API endpoint？ → A: 優先 /iframe/merchant_trade + CreditHash（選項 A），fallback 為 /api/credit + CreditHash（選項 B）。測試時若 merchant_trade 不支援純 token 續扣，切換到 fallback。
- Q: Token 儲存的 gateway_id 應該用什麼策略？ → A: 新 Token 使用 payuni-credit-subscription-v3。但續扣時 get_card_hash() 同時搜尋 payuni-credit-subscription-v3 + payuni-credit-subscription 兩個 gateway_id（選項 A: 雙 gateway_id 搜尋），讓 V1 舊 Token 的 CreditHash 也能在 V3 續扣中使用。搜尋優先序：先查 V3，找不到再查 V1。V1 舊 Token 保持原樣不遷移。
- Q: V3 零元訂閱如何取得 CreditHash？ → A: V3 走 UNi Embed iframe 扣 5 元（TradeAmt=5）+ merchant_trade 取得 CreditHash，排程 2 分鐘取消授權（選項 A）。流程與首次付款一致，只是金額為 5 元。
- Q: 續扣失敗後的重試策略？ → A: 與 V1 一致（選項 A），failed -> pending，由 WC Subscriptions 內建重試排程管理。
- Q: 訂閱生命週期操作是否需與 PayUni API 互動？ → A: 完全由 WC Subscriptions 管理（選項 A），暫停/恢復/取消不通知 PayUni，與 V1 一致。
- Q: V3 換卡流程？ → A: 利用 WC Subscriptions 內建換卡流程（選項 B），導向結帳頁面重新綁卡。結帳頁已有 UNi Embed SDK，不需在 My Account 額外載入。
- Q: V1 與 V3 定期定額閘道的共存策略？ → A: 透過後台設定由管理員決定顯示哪一個（選項 C）。管理員可在後台選擇使用 V1 或 V3 定期定額閘道。
- Q: 訂閱付款是否允許分期？ → A: 不允許分期（選項 A），前端隱藏分期選項，與 V1 一致。
